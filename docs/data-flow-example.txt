================================================================================
STEP 1: GitHub sends webhook to smee.io
================================================================================

You push commit "e01c557" to branch "fix/h2-local-dev" which has an open PR #3.
GitHub fires a webhook to: https://smee.io/DznJQUlwerxd9vi7

The smee client running locally forwards it to: http://localhost:8080/webhook/github

HTTP Request Headers (sent by GitHub automatically on every webhook delivery):

  X-GitHub-Event: pull_request
    → Tells you WHAT happened. GitHub sets this based on the event type.
      Examples: "pull_request", "push", "workflow_run", "issues", "ping"
      Your code uses this to decide which handler to call.

  X-GitHub-Delivery: a1b2c3d4-5678-90ab-cdef-1234567890ab
    → A unique UUID generated by GitHub for EVERY webhook delivery.
      No two deliveries ever share the same ID. Used for:
      - Deduplication (if the same event is delivered twice due to retry)
      - Debugging (you can find this ID in GitHub → Settings → Webhooks → Recent Deliveries)

  X-Hub-Signature-256: sha256=9f8e7d6c5b4a3210fedcba0987654321abcdef1234567890abcdef1234567890
    → SECURITY. GitHub computes HMAC-SHA256(webhook_secret, request_body) and puts the
      hex digest here. Your backend does the same computation with its copy of the secret
      (GITHUB_WEBHOOK_SECRET from .env) and compares. If they don't match, the request
      is rejected — someone is faking webhooks.
      Format: "sha256=" + hex(HMAC-SHA256(secret, body))

  Content-Type: application/json
    → Standard HTTP header. The body is JSON.

HTTP Request Body (GitHub webhook payload — abbreviated):
{
  "action": "synchronize",

================================================================================
STEP 2: WebhookController.handleGithubWebhook() receives it
================================================================================

File: WebhookController.java

1. Verifies HMAC-SHA256 signature:
   - Computes HMAC of the body using GITHUB_WEBHOOK_SECRET
   - Compares with X-Hub-Signature-256 header
   - If mismatch → returns 401

2. Deduplication check:
   - workflowRunRepository.existsByDeliveryId("a1b2c3d4-5678-90ab-cdef-1234567890ab")
   - If exists → returns 200 with {duplicate: true}

3. Checks event type:
   - event = "pull_request", action = "synchronize" → matches isOpenedOrSynchronize()
   - Calls handlePullRequest(payload, deliveryId)

STEP 6A: User clicks APPROVE
================================================================================

Dashboard calls: POST /api/reviews/{id}/approve

ReviewController.approveReview():
1. Sets review status = "approved"
2. Gets the WorkflowRun and its triggerPayload
3. Extracts the patch from review.payload
4. Calls gitHubService.pushPatchAsPRComment(repo, prNumber, patch):

   a. Gets PR head branch:
      - GET /repos/harshitm0019/Agentic-workflows/pulls/3
      - Returns head.ref = "fix/h2-local-dev"

   b. Splits patch by file:
      - File 1: "backend/src/test/java/com/agentic/ApplicationStartupTest.java"

   c. For each file:
      - Gets current content from GitHub (base64 decoded)
      - Applies the diff hunks to produce new content
      - Pushes commit:
        PUT /repos/harshitm0019/Agentic-workflows/contents/backend/src/test/java/...
        Body: { message: "fix: apply suggested changes from Agentic Workflows", content: <base64>, branch: "fix/h2-local-dev", sha: <file-sha> }

5. Sets WorkflowRun status = "completed"

================================================================================
STEP 6B: User clicks REJECT
================================================================================

Dashboard calls: POST /api/reviews/{id}/reject  Body: { reason: "Don't want this change" }

ReviewController.rejectReview():
1. Sets review status = "rejected", decisionReason = "Don't want this change"
2. Calls workflowEngine.resumeAfterReview(workflowRunId, false, reason)
3. WorkflowRun status → "failed", error = "Review rejected: Don't want this change"

No code is pushed to GitHub.

================================================================================
FAILURE ANALYSIS FLOW (separate workflow)
================================================================================

Triggered when: GitHub Actions CI fails (workflow_run event with conclusion: "failure")

Webhook payload (abbreviated):
{
  "action": "completed",
  "workflow_run": {
    "id": 12345678,
    "name": "Build Backend",
    "conclusion": "failure",
    "head_branch": "fix/h2-local-dev",
    "head_sha": "e01c557abc123"
  },
  "repository": { "full_name": "harshitm0019/Agentic-workflows" }
}

Flow:
1. WebhookController detects workflow_run + failure
2. Dedup check: "failure:harshitm0019/Agentic-workflows:fix/h2-local-dev:e01c557abc123"
3. Fetches logs: GET /repos/.../actions/runs/12345678/logs → returns ZIP file
4. Extracts text from ZIP entries, truncates to 50K chars
5. Starts failure-analysis workflow:
   - Step 1 (log-analysis agent): Analyzes logs → returns rootCause, affectedFiles, suggestedFix
   - Step 2 (change-suggestion agent): Generates patch → pauses for review

================================================================================
KEY POINTS
================================================================================

• The diff sent to the code-review agent is the FULL PR diff (all files changed vs main),
  not just the latest commit. Every push triggers a re-review of the entire PR.

• The change-suggestion agent only sees the FINDINGS from step 1, not the original diff.
  It generates a patch based on those findings alone.

• When approved, pushPatchAsPRComment splits multi-file patches and applies each file
  separately to avoid cross-contamination.

• The commit pushed by the platform starts with "fix: apply suggested changes from Agentic
  Workflows" — this prefix is checked on the next webhook to prevent infinite review loops.

• Failure analysis is deduplicated per commit SHA — multiple CI workflows failing on the
  same commit only trigger one analysis, but a new commit gets fresh analysis.
